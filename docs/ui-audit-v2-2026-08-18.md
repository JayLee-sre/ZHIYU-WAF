# ZHIYU-WAF V2 控制台与监控大屏 UI 审计基线

审计时间：2026-08-18（GMT+8）

## 生产访问结论

生产控制台的未认证访问会一致地重定向至 `/login`，包括 `/dashboard` 与 `/soc-dashboard`；认证边界工作正常。登录页目前仍采用左侧蓝色品牌面板、右侧白色表单的双栏结构。由于审计浏览器未持有管理员会话，本次监控大屏和主工作台的视觉基线以源码实现为准，不使用或猜测用户凭据。

## 主要问题

| 区域 | 当前问题 | 重构方向 |
| --- | --- | --- |
| 监控大屏 | 使用浅色背景和普通白卡片，和“安全运营大屏”的沉浸感不匹配；三栏布局中间地图空间不足，卡片层级同质化。 | 将独立大屏改为深色专用主题，以深海蓝底色、网格纹理、发光态势点和高对比数据为主；桌面端强调大地图与实时趋势。 |
| 监控大屏 | 24h 趋势由 24 个零值占位数组渲染，不能反映真实攻击走势。 | 复用已有 `/dashboard/timeseries` 数据接口，以 ECharts 实现请求、拦截、高风险三条真实序列。 |
| 监控大屏 | 仅有 30 秒刷新，缺少最后同步状态、刷新提示与数据更新时间；防护状态仅为三个小数字。 | 加入“实时刷新 / 最后同步 / 刷新按钮”状态条，防护状态转为能力健康清单。 |
| 主工作台 | `Dashboard.vue` 将模板、脚本及整套样式压缩为 62 行，难以维护；手写柱形图的表现力不足，视觉语言和其他页面割裂。 | 改为语义清晰的组件结构与独立样式块；改用 ECharts 趋势图，统一卡片、告警、标签和数据表格的视觉系统。 |
| 全局外壳 | 侧栏每项同时展示名称与说明、四个组均常驻，密度偏高；顶部又重复展示 AI、规则、系统状态，造成信息重复。 | 保留分组和关键运行状态，但压缩导航描述与信息冗余；采用更精炼的品牌区、活动态与状态胶囊。 |
| 设计系统 | 全局令牌已具备基础能力，但视图中存在大量局部硬编码色值，且浅色控制台与大屏未形成主题边界。 | 保持白色为主的控制台设计令牌；为独立 SOC 路由建立局部深色设计令牌，避免污染普通页面。 |

## 已确认的约束

1. 普通控制台继续以白色为主，避免杂乱和过重装饰。
2. 监控大屏是独立路由，可采用专业安全运营风格的深色专用主题。
3. 大屏必须保留：KPI、威胁等级、检测来源、全球/国内攻击地图、攻击来源 TOP、真实 24 小时趋势和防护状态。
4. 生产登录故障已修复：审计日志已记录 `dashboard login (legacy hash repaired)` 成功事件，健康检查为 `status: ok`。
5. 所有 GitHub 推送仍必须等待用户再次明确回复“确认推送”。
